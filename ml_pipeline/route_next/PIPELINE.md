## Исходный результат

TF-IDF + логистическая регрессия определила 5 из 10 маршрутов, Macro-F1 по представленным классам составил 0,333. По сохранённым агрегатам верно определены 4 из 5 вопросов о товаре и единственный запрос подбора. Ошибки пришлись на оба запроса выбора названного товара, оба уточнения и один вопрос о товаре. Передачи менеджеру в тесте отсутствовали. Исходные правила определили 5 из 10 маршрутов при Macro-F1 0,271. Старый тест закрыт для выбора и настройки следующей версии.

На обучении было 35 архивных и 30 синтетических реплик. Разнообразие русских формулировок, вариантов написания товарных названий и запросов редких классов ограничено. Словесные признаки сами по себе не подтверждают, является ли фрагмент названием продукта в каталоге. Это гипотезы, которые проверяются на новой валидации.

## Контракт следующей итерации

- На первом сообщении чата определить один из пяти следующих шагов: подбор названного продукта, подбор по задаче, ответ о конкретном товаре, уточнение, передача менеджеру. Использовать текст клиента; варианты с каталогом могут проверять только снимок, доступный на момент ответа.
- Проверить 184 новых кандидата вручную. Исключить реплики с ненадёжными границами, приватным контекстом и близкие дубли. По возможности отложить 40–60 новых реальных реплик со всеми пятью маршрутами, включая явные запросы менеджера. При нехватке редкого класса запросить дополнительные обращения. Синтетические проверки держать отдельно от метрик реального архива.
- Сравнить на одном новом наборе текущие правила, TF-IDF и семантический маршрутизатор на основе Haiku с проверкой названия по каталогу. Для внешнего вызова использовать только разрешённые обезличенные тексты. Сохранить объём выборки, Macro-F1, число верных маршрутов, полноту передачи менеджеру и ложные передачи. Замерить задержку отдельно для всех маршрутов и ходов с вызовом модели.
- Цель — улучшить Macro-F1 относительно правил и TF-IDF на той же выборке и сохранять обработку явных запросов менеджера. При отсутствии примеров передачи указывать, что полнота класса не измерена. Обновлять текущий маршрут только после независимой проверки.

## Сравнение после согласования

Model rationale:
- traits: 5 классов; 135 реплик для обучения, 43 для валидации и 49 для финального теста; последние две части только из архива. В каждой контрольной части по одному подбору по задаче и одной передаче менеджеру, поэтому выводы по ним диагностические. Дат диалогов в архиве нет.
- baseline: самый частый класс, исходные правила и прежняя TF-IDF-модель. Также обучить TF-IDF по словам + логистическую регрессию на расширенной выборке, чтобы измерить вклад разметки.
- candidates: сравнить признаки слов и символов с балансировкой классов, а также семантическую маршрутизацию Haiku с проверкой по каталогу. Для Haiku замерить отдельные задержки, ошибки API и частоту перехода на резервный маршрут. При передаче текстов провайдеру использовать только утверждённые обезличенные реплики.
- ruled out: обучение языковой модели с нуля и дообучение Haiku на текущем объёме данных. Замороженная часть остаётся закрыта для выбора признаков, модели и порогов.
- metric: Macro-F1, число верных маршрутов, размер каждого класса, полнота и ложные срабатывания передачи менеджеру. Результат по одному случаю публикуем с числом примеров.

## Мониторинг и переобучение

При проверке в тени на новом потоке собирать обезличенную ручную разметку, объём каждого маршрута, Macro-F1, частоту пропущенных уточнений, ложных передач и долю известных товаров, подтверждённых каталогом. Сравнивать с действующей логикой на одних диалогах и измерять задержку маршрута. Начинать новый цикл при устойчивом ухудшении на новой размеченной выборке или изменении источника каталога. Следующий тест формировать из новых обращений с отдельным покрытием подбора, уточнений и передачи. Использованный набор оставить закрытым для выбора порогов и кандидатов.
