Model rationale:
- traits: малые сценарные наборы, последовательные ходы внутри одного чата, факты привязаны к снимку каталога
- baseline: тот же рабочий агент с отключённой Polza
- candidates: агент с действующей моделью Haiku через штатный фильтр, настройки фиксированы
- ruled out: обучение маршрутизатора, смена модели или подбор порога на сценариях приёмки
- metric: доля целых успешных сценариев, проверки карточек и источников, эскалации, p95, успешные вызовы облака

## Как устроен прогон

Экран и HTTP-маршруты используют тот же код API и worker. Скрипт запускает HTTP-запросы через TestClient и выделяет отдельную схему в `TEST_DATABASE_URL` для каждого режима. Длительность включает HTTP-обработку и ход worker без ожидания интервала опроса в Compose. Для валидации можно повторить команду:

```sh
python -m ml_pipeline.agent_eval.run validation --catalog /path/to/catalog.sqlite --mode offline --output /tmp/validation-offline.json
python -m ml_pipeline.agent_eval.run validation --catalog /path/to/catalog.sqlite --mode live --output /tmp/validation-live.json
```

Во втором режиме переменные Polza берутся из окружения или из переданного локального `--env-file`. Статистика и разобранные исходы доступны в ноутбуках `03_model.py` и `04_eval.py`.
