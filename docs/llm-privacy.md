# Проверка сообщения перед внешним вызовом

ML-модуль `aisupport_ml.privacy` работает локально. Для распознавания имён и местоположений установите дополнительную зависимость `pip install '.[privacy]'`. Модель Natasha поставляется в пакете и загружается при первой проверке. Во время распознавания запросов в сеть нет.

Перед внешним вызовом передайте в `prepare_llm_input` текущую реплику, прошлые реплики, которые рассматриваются для использования, сохранённый серверный контекст подбора и признак вложения. Проверка артикула должна использовать доверенный индекс каталога. По умолчанию артикулы не разрешаются.

```python
from dataclasses import asdict

from aisupport_ml.privacy import prepare_llm_input

checked = prepare_llm_input(
    text,
    history=tuple(previous_customer_messages),
    selection=asdict(catalog_context) if catalog_context is not None else None,
    has_attachments=has_attachments,
    is_public_reference=lambda ref: len(catalog.by_reference(ref)) == 1,
)
payload = checked.model_payload
if payload is None:
    # Продолжить локально или передать обращение менеджеру.
    ...
else:
    # Передать модели только payload, при необходимости отрисовав его фиксированным шаблоном.
    ...
```

Например, для резервного копирования на 10 компьютерах с Windows 11 наружу можно передать `{"task":"backup","platform":"windows_11","device_count":10}`. Остальные поля собираются по тому же принципу из фиксированного списка. Бюджет, исходные строки контекста и история не сериализуются.

`masked_message` предназначен для локального просмотра и разбора. Он содержит маски для распознанных ФИО, контактов, идентификаторов и других значений. Весь объект результата сериализовать в запрос нельзя. `categories` содержит коды обнаруженных правил, пригодные для техлогов. Для локального текста маскирование вероятностное, особенно при нестандартном написании или косвенных описаниях. Объект для внешнего запроса строится отдельно только из разрешённых значений.

Вызов блокируется при признаках чувствительной информации, вложении, сбое распознавания, неподдерживаемой форме состояния, конфликтующих требованиях или отсутствии разрешённых полей. Числа вроде версии Windows и проверенного артикула не удаляются по общему правилу. Текстовые поля сохранённого состояния с совпадениями не участвуют в подготовке запроса.

Интеграция с HTTP-клиентом остаётся в бэкенде. Оба пути в Polza должны использовать только `model_payload`, включая повтор сообщения. Для существующей схемы каталожного извлечения формируйте сообщение из этих полей и сверяйте ответ с фактически отправленным текстом. Сохранённые требования передавайте только при продолжении текущей задачи.

Проверка на вымышленных сообщениях запускается через `python -m pytest tests/test_privacy.py`. Для старта сервиса без дополнительной зависимости проверка номеров и почты доступна локально, внешний запрос блокируется.
