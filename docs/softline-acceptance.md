# Приёмка демо Softline

Проверки используют те же HTTP-маршруты, что и клиентский и менеджерский экраны. Каждый сценарий создаёт свой чат. Набор содержит положительные и отрицательные проверки, сравнение вариантов, уточнения, вопросы по карточке и передачу менеджеру.

## Воспроизведение

Из каталога репозитория соберите синтетический индекс в отдельной директории.

~~~sh
mkdir -p /tmp/softline-demo
python -m softline_backend.catalog fixtures/softline/catalog.xml /tmp/softline-demo/catalog.sqlite3
~~~

Задайте `MANAGER_TOKEN` в окружении и запустите стенд с индексом, как описано в README. Из второго терминала с тем же `MANAGER_TOKEN` запустите API-проверку.

~~~sh
python -m evals.run_softline fixtures/softline/acceptance.json --output /tmp/softline-demo/acceptance.json
~~~

Для браузерного прогона установите Playwright и Chromium через `npm install --no-save --no-package-lock playwright` и `npx playwright install chromium`, затем выполните `node evals/browser_softline.cjs`. По умолчанию оба прогона используют `http://127.0.0.1:8000`. Для другого адреса передайте `--base-url` в API-прогоне и `SOFTLINE_BASE_URL` в браузерном. Для реальной выгрузки передайте свой манифест и задайте `BROWSER_CATALOG_QUERY` и `BROWSER_EXPECTED_SOURCE` по проверяемой карточке.

Для оценки стоимости добавьте `--usage-log /path/to/worker.log` и действующие тарифы `--input-rub-per-million` и `--output-rub-per-million`. Скрипт учитывает только записи Polza, относящиеся к ходам текущего прогона. Без полных счётчиков и тарифов оценка остаётся пустой.

## Контрольные прогоны

| Данные | Сценарии | Ходы | Ошибки проверки | p50 | p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Синтетический каталог | 3 | 11 | 0 | 503 мс | 665 мс |
| Фид Softline от 25.11.2026 с одним проверенным фактом из документации производителя | 3 | 12 | 0 | 501 мс | 669 мс |

Локальные замеры сделаны от HTTP-отправки до терминального статуса с учётом интервала опроса. Выборка небольшая. Браузер на обоих снимках проверил ссылку на карточку, восстановление чата после перезагрузки и доступ к истории после передачи менеджеру. Polza работала в режиме без внешних вызовов. Тарификация живой модели в этих прогонах не измерялась.

В реальном фиде 136 040 предложений, из них 44 601 отмечены доступными. У 44 978 предложений есть SKU, у 21 628 указан лимит пользователей. Часовой пояс выгрузки отсутствует, поэтому при импорте использовано допущение UTC+03:00. В реальном прогоне также проверено сравнение предложений MDaemon по ID. Указанные в спецификации редакция Standard и российский вариант для задачи на 50 сотрудников в проверенных источниках не подтвердились. Положительная рекомендация и сохранение фильтров проверены на синтетике. Для положительной рекомендации на реальном каталоге нужны проверенные сведения о возможностях, числе лицензированных пользователей и составе цены выбранных предложений.
