# Store Advisor

Рабочее место сотрудника Softline Store для кейса «ИИкузница». React, TypeScript, Vite и Motion.

## Запуск

```sh
npm ci
npm run dev
```

Клиентский чат доступен по `?view=chat`. Параметр `&product=astra-voronezh` добавляет контекст лицензии Astra Linux. Подбор использует фикстуры, а переданные обращения появляются в демо-журнале на том же адресе и в том же браузере.

В журнале можно искать запросы и фильтровать их по статусу и причине ручной проверки. Нажатие на строку открывает краткую карточку рядом с журналом. Кнопка «Полная карточка» открывает диалог, подбор и источники в текущей вкладке по отдельному адресу.

В полной карточке сотрудник нажимает «Взять в работу», после чего отвечает клиенту от имени поддержки. Enter отправляет сообщение, Shift+Enter добавляет новую строку. Можно приложить до пяти файлов общим размером до 10 МБ и скачать их из переписки. В деморежиме передача диалога, сообщения и файлы сохраняются в IndexedDB этого браузера.

В демо-журнале сотрудник может сменить статус и открыть следующий запрос на проверку. После передачи из клиентского чата откройте кейс менеджера во второй вкладке того же браузера. Если поставить «Ждём клиента» и отправить новую реплику из клиентского чата, запрос сразу вернётся на проверку с отметкой «Ответить».

## Подключение API

Укажите адреса бекенда в `.env.local` и перезапустите Vite:

```dotenv
VITE_AGENT_API_URL=/api/consultation
VITE_AGENT_REQUESTS_URL=/api/requests
VITE_SUPPORT_MESSAGES_URL=/api/support/messages
```

Адреса обслуживаются бекендом на том же origin или прокси. Для отдельного origin укажите полный URL и разрешите CORS на бекенде. Переменные доступны браузеру, поэтому указывайте только URL. При сборке для размещения задайте переменные до запуска `npm run build`.

Журнал делает JSON GET по `VITE_AGENT_REQUESTS_URL`. Ответ должен быть массивом `OperatorRequest` из `src/operator-types.ts`. Поле `response` содержит снимок диалога и результатов в формате `AgentResponse`. Если URL журнала не указан, используются данные `src/operator-mocks.ts`.

Окно «Тест агента» в боковой панели отправляет один JSON POST на сообщение по `VITE_AGENT_API_URL`:

```json
{
  "conversationId": null,
  "scenario": "known",
  "message": "Нужна Astra Linux",
  "history": [],
  "catalogProductId": "astra-linux-special-edition"
}
```

- `scenario` принимает значения `known`, `discovery`, `question` или `null`.
- `history` содержит предыдущие сообщения, каждое с полями `role` и `content`.
- `catalogProductId` берётся из параметра `?product=...` при переходе из каталога.
- В `reply` верните текст ассистента. Допустим также массив `messages`, из которого клиент покажет последнее сообщение ассистента.
- Ответ содержит ID диалога и данные для разбора обращения: `requirements`, `products`, `sources`, `trace`, `suggestedReplies`. Типы доступны в `src/agent-types.ts`.
- Логика обращения к API находится в `agent-client.mjs`. При пустом URL он вызывает `mock-agent.mjs` с тем же контрактом.

Полная карточка отправляет JSON POST на `VITE_SUPPORT_MESSAGES_URL`. Запрос содержит `requestId`, `conversationId` и `action`.

- `action: "takeover"` передаёт диалог сотруднику. Бекенд должен сохранить смену режима и прекратить автоответы агента до ответа 2xx.
- `action: "message"` отправляет клиенту `content` от имени поддержки. `clientMessageId` одинаков для повторной попытки без изменения черновика и служит ключом идемпотентности. Необязательный массив `attachments` содержит `name`, `contentType`, `size` в байтах и `contentBase64` без префикса data URL. При отправке только файлов `content` пустой. Ответ 2xx означает принятие сообщения каналом поддержки.
- GET журнала может возвращать `handledBy: "support"` и сообщения с `role: "support"`. Для ответов сотрудника передавайте `clientMessageId`; для доступных к скачиванию вложений укажите `attachments` с полями `name`, `size` и `url`.
